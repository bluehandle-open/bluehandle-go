# 蓝色手柄通信协议

本文档描述电脑端与安卓端之间的协议，安卓端仓库 bluehandle 和电脑端仓库 bluehandle-go 各存一份，**内容保持一致**，修改时两边同步。安卓端是协议的权威实现，电脑端不得改动已有的字节布局，否则现有 App 无法工作。

## 1. 连接

手机是服务端，电脑端主动连接。

- **Wi‑Fi**：手机监听 TCP 端口，默认 **8088**，可在手机「设置 → 连接」里修改。没有握手，连接建立后双方直接收发。
- **蓝牙**：RFCOMM，服务名 `MyBluetoothApp`，UUID `00001101-0000-1000-8000-00805F9B34FB`。连接建立后手机先发一行 `MyBluetoothApp\r\n`，电脑端比对通过后才开始收发。Go 版电脑端不再支持蓝牙。

## 2. 帧格式

两个方向的头部字节顺序**不同**，这是 Java 实现遗留下来的，必须照旧。

### 2.1 手机 → 电脑

```
+------+----------+-------------------+
| type | totalLen | body (totalLen-2) |
+------+----------+-------------------+
```

- `totalLen`：头部 2 字节加 body 的总长度，按**无符号**字节读取。没有结束符。
- 电脑端遇到不认识的 `type`，按 `totalLen` 跳过整帧，**不要断开连接**。

### 2.2 电脑 → 手机

```
+----------+------+-------------------+----+----+
| totalLen | type | body (totalLen-2) | CR | LF |
+----------+------+-------------------+----+----+
```

- 安卓端用 `BufferedReader.readLine()` 读取，所以每帧**必须以 CRLF 结尾**，body 中**不能出现 0x0A 或 0x0D**。
- `totalLen` 不包含结尾的 CRLF。
- 安卓端读到的是字符串再 `getBytes()`，所以 body 中的字节必须小于 0x80，否则会被字符集转换破坏。

### 2.3 长度上限

两端的 Java 代码都把 `totalLen` 存在有符号 `byte` 里，因此一帧最多 **127 字节**。文本消息超过这个长度时分成多帧发送（见第 6 节）。

## 3. 消息类型

| 值 | 名称 | 方向 | body | 说明 |
|---|---|---|---|---|
| 0x02 | 按键 | 手机 → 电脑 | `[flags, key1, key2, ...]` | 见第 5 节 |
| 0x10 | 手柄按键表 | 电脑 → 手机 | 12 个键码 | 手机按此表把虚拟按钮映射到键码 |
| 0x20 | PPT 按键表 | 电脑 → 手机 | 7 个键码 | 旧版遗留，新版手机不再使用 |
| 0x30 | 播放器按键表 | 电脑 → 手机 | 18 个键码 | 旧版遗留，新版手机不再使用 |
| 0x40 | 结束 | 双向 | 空 | 对方即将断开 |
| 0x41 | 心跳请求 | 手机 → 电脑 | 空 | Wi‑Fi 下手机每秒发一次，电脑端**不回复** |
| 0x42 | 心跳响应 | 未使用 | 空 | 两端都定义了，谁也没发过 |
| 0x50 | 文本输入 | 手机 → 电脑 | `[flags, UTF-8...]` | 语音输入使用，见第 6 节 |
| 0x51 | 锁屏 | 手机 → 电脑 | 空 | 遥控器锁屏键使用，见第 7 节 |

## 4. 键码

线上键码一律是 **Windows 虚拟键码**（`VK_*`），一个字节。字母和数字等于其大写 ASCII 码，shift=0x10，ctrl=0x11，alt=0x12，esc=0x1B，←↑→↓=0x25–0x28，F1–F12=0x70–0x7B。其他平台的电脑端自行把 Windows 键码翻译成本平台的按键。

安卓端旧版自定义按键表里混入了几个非 Windows 的值，电脑端按下表兼容转换：

| 线上值 | 含义 | 转换为 |
|---|---|---|
| 45 (0x2D) | `-` | 0xBD `VK_OEM_MINUS`（Windows 里 0x2D 本是 Insert） |
| 127 (0x7F) | Delete | 0x2E `VK_DELETE`（Windows 里 0x7F 本是 F16，安卓端 F16 与 DEL 共用此值，按 Delete 处理） |
| 155 (0x9B) | Insert | 0x2D `VK_INSERT`（Java 的 `VK_INSERT`） |
| 59–64 | `; < = > ? @` | 不转换。这些值在 Windows 里未定义，注入时按字符输入 |

改版后新增使用的键码：

| 键码 | 含义 | 使用位置 |
|---|---|---|
| 0x08 / 0x0D | 退格 / 回车 | 数字键页、遥控器 OK |
| 0x30–0x39 / 0xBE | 数字 0–9 / 主键盘句点 | 数字键页 |
| 0x5B | 左 Win | 遥控器「桌面」发 Win+D |
| 0x5D | 右键菜单键 | 遥控器「菜单」 |
| 0x12 + 0x09 | Alt+Tab | 遥控器「切换窗口」 |
| 0xAD / 0xAE / 0xAF | 静音 / 音量减 / 音量加 | 遥控器 |
| 0xB0 / 0xB1 / 0xB3 | 下一曲 / 上一曲 / 播放暂停 | 遥控器 |
| 0x21 / 0x22 | PgUp / PgDn | 遥控器翻页、PPT 翻页 |
| 0x10 + 0x74 | Shift+F5 | PPT 从当前页放映 |
| 0x42 | B | PPT 黑屏 |

Windows 上用 `SendInput` 模拟媒体键（0xAD–0xB3）、方向键、Insert/Delete、PgUp/PgDn 时需要设置 `KEYEVENTF_EXTENDEDKEY`。

## 5. 按键消息（0x02）

```
body[0]  flags：bit0 = 按下，bit1 = 抬起，可同时置位（3 = 按下并立即抬起）
body[1:] 键码列表，一次动作里可以有多个键（组合键）
```

电脑端处理顺序：若 bit0 置位，按列表顺序逐个按下；再若 bit1 置位，按列表顺序逐个抬起。键码为 0 的字节跳过（自定义按键方案固定 3 个键位，不足的用 0 补齐）。Java 端把负字节与 `0xff` 相与，等价于按无符号读取。

示例，按下 W 和 S：

```
02 05 01 57 53
```

抬起同样两个键：

```
02 05 02 57 53
```

遥控器上的方向键、音量键、翻页键支持按住：手指按下时发 bit0，抬起时发 bit1，中间的连发交给电脑系统的按键重复。其余键一次发 3。

## 6. 文本输入（0x50）

```
body[0]  flags：bit0 = 文本输入完后再按一次回车
body[1:] UTF-8 文本
```

- 每帧正文不超过 **120 字节**，且不会把一个字符拆到两帧里，所以每帧都是完整合法的 UTF-8。长文本连续发多帧，**只有最后一帧可能带回车标志**。电脑端逐帧输入即可，不需要拼接缓存。
- 正文可以为空，此时只表示按一次回车。
- 文本必须用 Unicode 方式输入，例如 Windows 的 `SendInput` 配合 `KEYEVENTF_UNICODE`，不能翻译成虚拟键码，否则会受当前输入法影响。
- 回车按第 4 节的 0x0D 处理。

示例，输入「你好」后回车（「你好」的 UTF-8 为 `E4 BD A0 E5 A5 BD`）：

```
50 09 01 E4 BD A0 E5 A5 BD
```

## 7. 锁屏（0x51）

```
51 02
```

电脑端应调用系统锁屏接口，Windows 上是 `LockWorkStation()`。用 Win+L 模拟按键会被 Windows 拦截，不会生效。

## 8. 按键表消息（0x10 / 0x20 / 0x30）

示例，电脑端发送手柄按键表：

```
0E 10 57 53 41 44 55 49 4F 4A 4B 4C 31 35 0D 0A
```

即 `totalLen=14`，`type=0x10`，12 个键码（w s a d u i o j k l 1 5），CRLF 结尾。

注意：Java 电脑端发送的手柄表顺序是 `w s a d u i o j k l 1 5`，而安卓端内置默认表顺序是 `w s a d 1 5 u i o j k l`，两者对 X/Y/select/start 四个按钮的映射不一致。Go 版沿用电脑端顺序，这个差异留待两端一起核对。

## 9. 连接结束

- 电脑端退出时发送 `02 40 0D 0A`，然后关闭 socket。
- 手机端主动断开时发送 `40 02`，然后关闭 socket；电脑端收到后应提示「手机端退出」。手机端从遥控界面返回首页不会断开，只有在首页点「断开」才会。
- 电脑端连续 5 秒没有收到任何帧（含心跳）即判定手机掉线。Java 版的判定方式是每条消息后发 TCP 紧急数据探测，Go 版不再这样做。

## 10. 已知缺陷（保持兼容，暂不修改）

1. 两个方向头部顺序不一致。
2. 电脑 → 手机依赖换行符分帧，body 不能含 CR/LF，也不能含大于 0x7F 的字节。
3. `totalLen` 为有符号字节，上限 127。
4. 心跳只有单向，电脑端从不应答。
5. 安卓端旧按键表里 127 同时表示 Delete 和 F16。
