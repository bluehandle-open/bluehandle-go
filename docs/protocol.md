# 蓝色手柄通信协议

本文档描述电脑端与安卓端之间的 TCP 协议，内容根据 Java 版电脑端（bluehandle-pc）和安卓端源码整理。安卓端是协议的权威实现，电脑端重写时**不得改动任何字节布局**，否则现有 App 无法工作。

## 1. 连接

- 安卓端在手机上监听 TCP 端口 **8088**，电脑端主动连接。
- Wi-Fi 方式**没有握手**：连接建立后双方直接收发消息。
- 蓝牙 RFCOMM 方式（已在 Go 版中废弃）会先由手机发送一行 `MyBluetoothApp\r\n`，电脑端比对后才开始收发。

## 2. 帧格式

两个方向的头部字节顺序**不同**，这是 Java 实现遗留下来的，必须照旧。

### 2.1 手机 → 电脑

```
+------+----------+-------------------+
| type | totalLen | body (totalLen-2) |
+------+----------+-------------------+
```

- `type`：消息类型，见第 3 节。
- `totalLen`：头部 2 字节加 body 的总长度。
- 没有结束符。

### 2.2 电脑 → 手机

```
+----------+------+-------------------+----+----+
| totalLen | type | body (totalLen-2) | CR | LF |
+----------+------+-------------------+----+----+
```

- 安卓端用 `BufferedReader.readLine()` 读取，所以每帧**必须以 CRLF 结尾**，并且 body 中**不能出现 0x0A 或 0x0D**。
- `totalLen` 不包含结尾的 CRLF。
- 安卓端读到的是字符串再 `getBytes()`，所以 body 中的字节必须小于 0x80，否则会被字符集转换破坏。

### 2.3 长度上限

两端的 Java 代码都把 `totalLen` 存在有符号 `byte` 里，因此一帧最多 **127 字节**。将来语音文本消息超过这个长度时需要分片。

## 3. 消息类型

| 值 | 名称 | 方向 | body | 说明 |
|---|---|---|---|---|
| 0x02 | 按键 | 手机 → 电脑 | `[flags, key1, key2, ...]` | 见第 4 节 |
| 0x10 | 手柄按键表 | 电脑 → 手机 | 12 个键码 | 手机按此表把虚拟按钮映射到键码 |
| 0x20 | PPT 按键表 | 电脑 → 手机 | 7 个键码 | |
| 0x30 | 播放器按键表 | 电脑 → 手机 | 18 个键码 | 六组 ctrl+alt+X |
| 0x40 | 结束 | 双向 | 空 | 对方即将断开。手机收到后不做处理，电脑收到后关闭连接并提示 |
| 0x41 | 心跳请求 | 手机 → 电脑 | 空 | Wi-Fi 下手机每秒发一次，电脑端**不回复** |
| 0x42 | 心跳响应 | 未使用 | 空 | 两端都定义了，谁也没发过 |
| 0x50 | 文本 | 电脑 ← 手机（预留） | UTF-8 文本 | 语音输入用，尚未实现 |

键码一律使用 Java `java.awt.event.KeyEvent` 的 `VK_*` 值，因为安卓端存的就是这个。常用值：字母和数字等于其大写 ASCII 码，shift=16，ctrl=17，alt=18，esc=27，←↑→↓=37/38/39/40，F5=116，F6=117。

## 4. 按键消息（0x02）

```
body[0]  flags：bit0 = 按下，bit1 = 抬起，可同时置位
body[1:] 键码列表，一次动作里可以有多个键（组合键）
```

电脑端处理顺序：若 bit0 置位，按列表顺序逐个按下；再若 bit1 置位，按列表顺序逐个抬起。键码为 0 的字节跳过。Java 端把负字节与 `0xff` 相与，等价于按无符号读取。

示例，按下 W 和 S：

```
02 05 01 57 53
```

抬起同样两个键：

```
02 05 02 57 53
```

## 5. 按键表消息（0x10 / 0x20 / 0x30）

示例，电脑端发送手柄按键表：

```
0E 10 57 53 41 44 55 49 4F 4A 4B 4C 31 35 0D 0A
```

即 `totalLen=14`，`type=0x10`，12 个键码（w s a d u i o j k l 1 5），CRLF 结尾。

注意：Java 电脑端发送的手柄表顺序是 `w s a d u i o j k l 1 5`，而安卓端内置默认表顺序是 `w s a d 1 5 u i o j k l`，两者对 X/Y/select/start 四个按钮的映射不一致。Go 版沿用电脑端顺序，这个差异留待两端一起核对。

## 6. 连接结束

- 电脑端退出时发送 `02 40 0D 0A`，然后关闭 socket。
- 手机端退出时发送 `40 02`，然后关闭 socket；电脑端收到后应提示“手机端退出”。
- Go 版额外规定：电脑端连续 5 秒没有收到任何帧（含心跳）即判定手机掉线。Java 版的判定方式是每条消息后发 TCP 紧急数据探测，Go 版不再这样做。

## 7. 已知缺陷（保持兼容，暂不修改）

1. 两个方向头部顺序不一致。
2. 电脑 → 手机依赖换行符分帧，body 不能含 CR/LF，也不能含大于 0x7F 的字节。
3. `totalLen` 为有符号字节，上限 127。
4. 心跳只有单向，电脑端从不应答。
